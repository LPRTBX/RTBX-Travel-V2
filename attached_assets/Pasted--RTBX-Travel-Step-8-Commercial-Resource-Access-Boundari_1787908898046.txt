# 1. Objective

Ensure the external RTBX Travel Partner Room contains only material appropriate for a prospective:

* hotel operator
* pilot customer
* technology partner
* deployment partner
* strategic commercial partner

Internal-only, investor-only and commercially sensitive material must not be exposed merely because it is hidden behind:

* navigation
* CSS
* route obscurity
* a client-side access code

The principle is:

> If content is sensitive, it must not be shipped in the external client bundle unless there is a genuine server-side access control.

---

# 2. Current access-boundary principle

The existing Partner Room access code is a **demonstration gate**, not a security boundary.

Therefore:

* do not call the environment secure
* do not call it confidential unless the content itself is safe to expose
* do not assume hidden routes are protected
* do not assume unlinked pages are private
* do not assume route knowledge protects sensitive content

Use a label such as:

> **Controlled Partner Preview**

or:

> **Partner Review Environment**

Avoid:

> Private

unless true security exists.

---

# 3. Resource classification

Review every resource, commercial page and route and classify it as one of:

## General Partner

Safe for a broad prospective partner.

Examples:

* Partner Overview
* Operating Model
* Pilot Model
* Partner Ecosystem
* Working Proof
* Commercial Pathway at high level

## Pilot Partner

Appropriate after pilot interest exists.

Examples:

* Pilot scope
* readiness framework
* deployment responsibilities
* configuration requirements
* measurement framework

## Technical Partner

Appropriate for system/integration discussion.

Examples:

* systems map
* integration architecture
* connector responsibilities
* technical maturity
* architecture overview

## Deployment Partner

Appropriate for implementation/change partners.

Examples:

* rollout model
* responsibility matrix
* configuration workflow
* training/change scope

## Commercially Restricted

Should not be generally available.

Examples:

* detailed unit economics
* negotiation assumptions
* partner margin assumptions
* confidential pricing logic
* commercially sensitive revenue split logic

## Internal Only

Must not ship in the external Partner Room.

Examples:

* Business Plan
* Go-to-Market Plan
* internal Revenue Model
* internal commercial forecasts
* investor assumptions
* funding strategy
* internal operating notes
* unapproved market assumptions
* internal architecture notes not intended for partners
