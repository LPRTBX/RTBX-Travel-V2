# 1. Objective

Ensure the RTBX Travel Partner Room works cleanly and intentionally across:

* phone
* tablet
* laptop
* desktop
* wide desktop

The current application contains many fixed multi-column grids and dense operational layouts.

The goal is:

> Preserve product depth while adapting the layout intelligently to the available screen width.

Do not solve responsive issues by:

* shrinking text below approved typography standards
* hiding important content
* using `overflow-x: hidden` to conceal clipping
* cutting off cards
* forcing desktop layouts onto tablets
* creating tiny controls

# 3. Global responsive rules

Review the active layout system.

The application should generally behave as:

## Mobile

320–639px

* single-column primary layout
* stacked cards
* mobile navigation
* full-width controls
* readable horizontal tabs
* no clipped content

## Large mobile / small tablet

640–767px

* mostly single column
* two-column layout only where genuinely readable
* mobile/tablet navigation

## Tablet

768–1023px

* one or two columns depending on content
* avoid five- or four-column grids
* use tablet navigation behaviour established in Step 3
* operational panels may stack

## Desktop

1024px+

* desktop multi-column layouts may apply
* preserve readable widths
* avoid unnecessarily wide text blocks

Adjust these ranges to the existing implementation where necessary, but the result must remain usable.

---

# 4. Remove overflow masking

Search global CSS and active layout components for patterns such as:

```css
overflow-x: hidden;
```

Do not rely on this rule to hide layout failures.

Where horizontal overflow is caused by an actual layout defect:

* fix the grid
* allow wrapping
* stack components
* adjust min-width
* add controlled local scrolling only where appropriate

Global `overflow-x: hidden` may remain only where there is a legitimate non-content reason and it does not conceal active UI.

Document any retained usage.
