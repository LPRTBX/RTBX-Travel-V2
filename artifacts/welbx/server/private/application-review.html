What would make this operational?

Both apps would read permitted views of the same durable Core coordination state. Counts would be calculated from the current authorised scope, not independently maintained in another app engine.

Before live use: verify identity and stay binding, scoped grants and revocation, plan-version checks, ownership and task acceptance, communication audiences, replay-safe writes, independent review and follow-up rules.

Where JALDO Core fits

The proposed apps present different views of one coordination record. Core is the intended place for authority checks, governed decisions, assignments and durable evidence. This story is static and has no runtime Core integration.

Guest app

Request, contact preference, safe progress and feedback.

JALDO Core · proposed connection

Authority, current plan, release, acceptance and recorded outcomes. Exact contract compatibility remains to be verified.

Staff workspace

Role-specific intake, ownership, review, work and follow-up.

From demonstration to a scoped pilot

One property. One practical-support journey.

Name the roles

Who receives requests, approves support, accepts work and reviews the outcome? Agree shift cover and unavailable-staff handling.

Agree the measures

Measure time to ownership, acceptance and delivery; outstanding tasks; guest-confirmed outcomes; and staff effort. Establish a baseline before making savings claims.

Prove the connection

Verify guest stay binding, scoped staff authority, durable writes, communication audiences and failure recovery against Core before using real data.

This defines a proposed pilot boundary. It does not approve data collection, live communication or operational release.

Privacy boundaries

Minimise at intake

Necessary facts and safe contact only. Keep diagnosis, payment details, identity documents and unrelated history out of request context.

Project on the server

Role switching is for this design only. Production must filter content, counts, identifiers, history and notification text server-side.

Agree retention before real data

Approve guest notice, lawful authority, retention/deletion, audit access, provider handling and incident procedure. No operational data enters this prototype.
